# cjt — Code Jump Tags

先分清用户要的是哪一样，**两条路不混用**：

| 用户要的 | 走哪条 | 产物 |
|---|---|---|
| 「用 cjt 做 X 链路追踪」「打标签」「侧边栏建文件夹」「顺读」「带我走一遍」 | **A. 单步调试式链路标签（cjtag）** | 侧边栏里按场景分组、按执行顺序排好的步骤，不产出 md |
| 写好的文档里的代码引用要能点 | **B. cjt.py 文档链接** | 原 md 里的引用变成 vscode:// 链接 |

「链路追踪」默认走 **A**。别为了 A 先写一份 md 再用 B 的 `--tags` 转——那只出一层平铺文件夹。

## A. 单步调试式链路标签（cjtag）

**目标是调试器单步的感觉**：用户点开一个场景，按 ▶「顺读此文件夹」，从入口一行行往下走，
遇到函数调用就步入，做完返回调用处，每一步都知道「这里干了什么、现在状态是什么、为什么下一步到那」。

**反例（用户明确说过不满意）**：按「类别」摆（出厂默认 / 设置 / 持久化 / 状态显示……），每条是个孤立的
地点标签——那是索引，不是单步，前后没有因果，读不连贯。

Code Jump Tags 扩展 ≥ 0.9.0 自带 CLI `cjtag`（在扩展目录的 `dist/cli.js`）。用 Bash 工具定位最新版：

```
CLI=$(ls -d ~/.vscode/extensions/patrick1099.code-jump-tags-* | sort -V | tail -1)/dist/cli.js
node "$CLI" --ai-help        # 完整说明
```

### 1. 先定场景（一个场景 = 一次完整的执行）

场景是「某个触发 → 一路执行到可见结果」，按用户会遇到的真实情形切，不按代码模块切：

- 数据从哪来：上电 / 出厂默认值怎么加载；
- 外部怎么改它：每个写入入口（平台协议、本地串口、按键……）各一个场景；
- 运行时怎么变：周期任务里怎么消耗 / 累计，到阈值发生什么；
- 结果怎么解除：谁能清掉、清完之后还差什么才恢复；
- 追踪中发现的**异常路径单独成场景**，标题带「（疑点）」，一步步走给用户看它哪里不对。

场景名写成「触发 → 结果」，带序号，如 `3 扣到用尽 → 关阀`、`5 平台开户 → 按键开阀`。
场景之间有前后依赖时，在第一步写明前提（「前提：场景 3 刚走完，阀已关」）。

### 2. 沿调用链逐行单步

- **先锁定编译变体**：同一套代码编多个 target（民用/商用、不同计量方式、不同客户）时，先问清或确认用户要哪一个，
  查出该 target 的宏定义（工程文件的 Define、配置头），只沿它实际编进去的 `#if` 分支单步；
  链路名标明变体（如 `预留量链路（商用超声波）`）。别把几个变体的路径混在一条链里——入口、阈值、默认值常常都不同。
- **从真正的入口开始**：`main`、中断回调、协议帧解析入口、周期任务入口——不从中间某个函数开始。
- **每个分支判断都是一步**：写出这次走哪边、为什么（「未开户 && 使能 → 进预留量分支；已开户会走下面的预付费」）。
- **函数调用**：步入写 `↳ 函数名`，函数里的关键行逐行走，走完回到调用处写 `↩`。
  无关紧要的调用（日志、纯 getter）不步入，在调用那一步一句话带过。
- **异步要点明**：挂定时器 / 回调 / 另一个任务轮询时，写清「不是在这里直接调用，下一拍由 X 执行」，
  再从执行它的那个任务的入口接着走。
- **状态要跟着走**：关键变量在这一步之后是什么值、哪些标志位被置 / 清，写进 note。
- note 以两位步号开头（`01 `、`02 `），侧边栏里也能看出顺序；顺读气泡另有 Step x of N。
- 追踪中发现的疑点写在它发生的那一步，不另开一个「疑点」目录收集。

### 3. 写清单、核对、导入

清单是 UTF-8 JSON 扁平数组，放 scratchpad（不放进被标注的仓库），**数组顺序就是单步顺序**：

```json
{"folder": "预留量链路/3 扣到用尽 → 关阀", "file": "Code/App/Code/app/meter/charge_manage.c", "line": 966, "note": "09 未开户 && 预留量使能 → 进预留量分支（已开户会走下面的预付费扣费）"}
```

`folder` 用 `/` 分层：一级是链路名，二级是场景。场景里一般不再分子文件夹，保持一条直线好顺读。

**导入前必须逐步核对源码行**（import 只校验行号没越界，不管是不是那一行；偏一行就讲错一步）：

```
py -3 ${CLAUDE_PLUGIN_ROOT}/scripts/check_steps.py <steps.json> --root <仓库根>
```

逐条看打印出的源码行和 note 对不对得上；有错改清单重跑，0 错误再导入：

```
node "$CLI" import <steps.json> --cwd <仓库根>
node "$CLI" list --folder "<链路名>" --cwd <仓库根>
```

某条校验不过（文件不存在 / 行号越界 / note 空）整批拒绝、不写入，按 `error.details` 的 index 修。

### 追加、重建、删除

- **给某个场景追加步骤，或新增一个场景**：只导**新增**条目，或单条
  `node "$CLI" add --folder "<链路名>/<场景>" --file F --line N --note TEXT --cwd <仓库根>`。
  要插在场景中间（不是末尾）时，整个场景 `clear` 后按新顺序重导。
- **import 不去重**：同一份清单导两次会出重复标签（实测）。要整棵重建，先
  `node "$CLI" clear --folder "<链路名>" --cwd <仓库根>` 再 import。
- `clear` 进回收站，用户可在侧边栏「从回收站恢复」；清之前先 `list` 确认是要清的那棵。
- store.json 有文件监听，写完侧边栏即时刷新，不用重载窗口。

### 交付时告诉用户

- 有哪几个场景、各多少步，一句话说每个场景走的是什么；
- 点场景文件夹上的 ▶「顺读此文件夹」开始单步，`Alt+]` 下一步、`Alt+[` 上一步；
- 单步中发现的疑点单独列出（在哪个场景第几步），说明没改代码。

## B. 文档跳转链接（cjt.py）

写文档时**正常写引用**，不要手工拼 URL。支持的引用写法（转换时自动识别）：

- `` `App/Code/main.c:123` ``（行内代码，最常用）
- `App/Code/main.c:123` 裸文本 / `App/Code/main.c:123-145` 行区间
- `[自定义标签](App/Code/main.c:123)`
- 裸引用与中文文字之间要留空格（或用行内代码包起来），否则路径会被误粘连

围栏代码块内的引用不会被转换；已是 `vscode://` 的链接不会二次转换（幂等）。

文档写完后执行一次：

```
py -3 ${CLAUDE_PLUGIN_ROOT}/scripts/cjt.py convert <doc.md> --format json
```

- 报告中 `misses` 为空 → 完成。
- 有 miss → 按 `reason` 核对该引用（`file-not-found`/`line-out-of-range` 通常是路径或行号写错；路径必须相对**工作区根**），改正文档后重跑。
- 文档在被引用仓库之外（如 Obsidian vault）→ 加 `--root <仓库根>`。
- 只要一条链接：`py -3 ${CLAUDE_PLUGIN_ROOT}/scripts/cjt.py link path:line [标签] --format json`。
- 文档本身就是主体、只想在侧边栏留一个「这份文档的跳转点」平铺文件夹时，convert 加
  `--tags --name "<名称>"`；重跑幂等，文档删改后再跑一次即同步。**要分类/分层就走 A。**
  已转换文档单独补写：`py -3 ${CLAUDE_PLUGIN_ROOT}/scripts/cjt.py tags <doc> --name <名称> --format json`。
- 单条进收件箱：`link path:line [标签] --tags`。

## 前提（对人说明，遇到"点了没反应"时提示用户）

- 需已安装 VS Code 扩展 Code Jump Tags（patrick1099.code-jump-tags）；A 需 ≥ 0.9.0。
- 点击时 VS Code 打开的第一个工作区文件夹必须是链接路径的根。
- 侧边栏实时刷新需扩展 ≥ 0.8.0；旧版需 Reload Window。
