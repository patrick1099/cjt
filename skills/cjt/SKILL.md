# cjt — Code Jump Tags

先分清用户要的是哪一样，**两条路不混用**：

| 用户要的 | 走哪条 | 产物 |
|---|---|---|
| 「用 cjt 做 X 链路追踪」「打标签」「侧边栏建文件夹」「带我走一遍」「教我追这条链路」 | **A. 引导式链路追踪（cjtag）** | 侧边栏里按场景分组的检查点，每点告诉用户下一步怎么手动跳，不产出 md |
| 写好的文档里的代码引用要能点 | **B. cjt.py 文档链接** | 原 md 里的引用变成 vscode:// 链接 |

「链路追踪」默认走 **A**。别为了 A 先写一份 md 再用 B 的 `--tags` 转——那只出一层平铺文件夹。

## A. 引导式链路追踪（cjtag）

**目标是像平时追链路那样，带用户自己走一遍**：标签是「检查点」，不是让用户按 Alt+] 自动播放的幻灯片。
每个检查点写清：这一行在看什么、状态怎么变；**下一步用哪种跳转、在哪个符号上、会跳到哪**。
用户自己按键跳过去，到了再点标签核对位置。

用户明确否掉过的两种做法：
- 按「类别」摆（出厂默认 / 设置 / 持久化……），每条是孤立的地点——那是索引，不连贯；
- 只给执行顺序、让用户按 Alt+] 顺读——看完了还是不会自己追。

Code Jump Tags 扩展 ≥ 0.9.0 自带 CLI `cjtag`（在扩展目录的 `dist/cli.js`）。用 Bash 工具定位最新版：

```
CLI=$(ls -d ~/.vscode/extensions/patrick1099.code-jump-tags-* | sort -V | tail -1)/dist/cli.js
node "$CLI" --ai-help        # 完整说明
```

### 1. 先锁定编译变体

同一套代码编多个 target（民用/商用、不同计量方式、不同客户）时，先问清或确认用户要哪一个，
查出该 target 的宏（工程文件的 Define、配置头），只沿它实际编进去的 `#if` 分支走；链路名标明变体
（如 `预留量链路（商用超声波）`）。顺手看一眼 `.clangd` / `compile_commands.json` 配的是哪个 target——
编辑器里灰掉的分支、调用层次里列出的调用者都取决于它，引导语要和用户实际看到的一致。

### 2. 跳转方式：实测后再写进引导语

写「▶ 下一步」之前，用 LSP 工具（goToDefinition / incomingCalls / findReferences）在目标仓库实测，
确认用户照做真能到达。常见规律（clangd 下实测，换仓库要复测）：

| 想追什么 | 引导用户用 | 注意 |
|---|---|---|
| 直接调用的函数，往里走 | **F12 转到定义** | 最常用 |
| 这个函数被谁调，往上找 | **右键 → 显示调用层次结构**（Shift+Alt+H） | 经 `TimeM_Start(…, fn)` 之类传函数指针的也能找到；会把其他 target 的调用者一起列出来，引导语要点明挑哪个 |
| 查表分发的函数往上找 | 显示调用层次结构 | 停在「表」这个变量上；再在表名上 Shift+F12 找到用表的函数 |
| 变量 / 结构体字段 / 枚举被谁读写 | **查找所有引用**（Shift+F12） | 很准，适合做起点清单 |
| 宏 | **全局搜索**（Ctrl+Shift+F） | clangd 不索引宏引用，Shift+F12 只有定义本身；宏上 F12 只给当前生效的定义，确认「有没有别处定义」必须全局搜 |
| `table[i].fn(...)` 函数指针成员 | 先在**表名**上 F12，表里找到对应项，再在函数名上 F12 | 直接在成员名上 F12 只到结构体声明，死路——要在引导语里点破 |
| 回到调用处 | **Alt+←**，或点前面某个检查点标签 | 跳了好几层时直接写「点 1.7 回到 Para_ReadAll」更稳 |

还要确认全局搜索能搜到源文件：有透明加密的机器上，VS Code 搜索调用的是自带 `rg.exe`，
用它对几个源文件实测一次能不能搜出明文。

### 3. 场景 0：先摸清读写点

平时追链路的起手式是从「状态」出发，不是从 main 出发。第一个文件夹固定叫 `0 起点：先摸清读写点`：
- 链路核心变量（结构体字段）上 Shift+F12：列出全部读写处，分清写 / 读，每处标注属于后面哪个场景；
- 外部模块走 setter / getter 的，在 setter、getter 上「显示调用层次结构」，列出调用者并映射到场景；
- 相关的枚举、状态位、配置项同样 Shift+F12 一次，按「置位 / 清除 / 检查」分类。

后面每个场景的第一步写「怎么找到的」：从场景 0 的哪一处出发，用什么跳转往上翻到这个入口。

### 4. 场景：一次完整的执行

场景是「某个触发 → 一路执行到可见结果」，按用户会遇到的真实情形切：
数据从哪来（上电 / 默认值）、每个外部写入口、运行时怎么消耗到阈值、结果怎么解除；
追踪中发现的**异常路径单独成场景**，标题带「（疑点）」。场景名写成「触发 → 结果」，带序号。
场景之间有前后依赖时，第一步写明前提（「前提：场景 3 走完，阀已关」）。

每个场景从真正的入口往下走（main、中断回调、协议帧解析入口、周期任务），检查点放在**用户要操作的那一行**：
- 每个检查点 = 「这一行在看什么 / 状态怎么变」+ `▶ 下一步：<跳转方式> 在 <符号> 上 → <会到哪>`；
- 同一函数里往下几行就到的，写「往下看 N 行」，不强行跳转；
- 挂定时器 / 回调 / 另一任务轮询的，写明「异步，不是在这里直接调用」，并引导去执行它的地方；
- 跳转会走进死路（函数指针成员、宏只给生效定义、调用层次混入其他 target）时，在那一步点破，给绕行方法；
- 追踪中发现的疑点写在它发生的那一步。

编号用「场景号.步号」，不补零：`6.1`、`6.12`；互相引用也用这个编号（「分发过程同 2.1~2.3」「对照 5.3~5.4」）。
不要每个场景都从 `01` 重新数。

### 5. 写清单、核对、导入

清单是 UTF-8 JSON 扁平数组，放 scratchpad（不放进被标注的仓库），**数组顺序就是追踪顺序**：

```json
{"folder": "预留量链路（商用超声波）/3 扣到用尽 → 关阀", "file": "Code/App/Code/wave/commercial/wave_JL_protocol.c", "line": 1648, "note": "3.4 又是查表 + 函数指针，在 ExeDataID 上按 F12 是死路。▶ 往上看 1630 行，在 s_JL_V2_CmdExeTable_FromBoard 上按 F12"}
```

`folder` 用 `/` 分层：一级是链路名，二级是场景，场景里不再分子文件夹。

**导入前必须逐步核对源码行**（import 只校验行号没越界，不管是不是那一行；偏一行引导就错）：

```
py -3 ${CLAUDE_PLUGIN_ROOT}/scripts/check_steps.py <steps.json> --root <仓库根>
```

逐条看打印出的源码行和 note 对不对得上；0 错误再导入：

```
node "$CLI" import <steps.json> --cwd <仓库根>
node "$CLI" list --folder "<链路名>" --cwd <仓库根>
```

某条校验不过（文件不存在 / 行号越界 / note 空）整批拒绝、不写入，按 `error.details` 的 index 修。

### 追加、重建、删除

- **给某个场景追加检查点，或新增一个场景**：只导**新增**条目，或单条
  `node "$CLI" add --folder "<链路名>/<场景>" --file F --line N --note TEXT --cwd <仓库根>`。
  要插在场景中间时，整个场景 `clear` 后按新顺序重导。
- **import 不去重**：同一份清单导两次会出重复标签（实测）。要整棵重建，先
  `node "$CLI" clear --folder "<链路名>" --cwd <仓库根>` 再 import。
- `clear` 进回收站，用户可在侧边栏「从回收站恢复」；清之前先 `list` 确认是要清的那棵。
- store.json 有文件监听，写完侧边栏即时刷新，不用重载窗口。

### 交付时告诉用户

- 有哪几个场景、各多少个检查点，一句话说每个场景追的是什么；
- 建议从场景 0 开始，照每条的 ▶ 自己跳，到了点标签核对；
- 实测得出的跳转规律（哪里 F12 是死路、哪里要全局搜）简要列一下；
- 追踪中发现的疑点单独列出（在哪个场景第几步），说明没改代码。

## B. 文档跳转链接（cjt.py）

写文档时**正常写引用**，不要手工拼 URL。支持的引用写法（转换时自动识别）：

- `` `App/Code/main.c:123` ``（行内代码，最常用）
- `App/Code/main.c:123` 裸文本 / `App/Code/main.c:123-145` 行区间
- `[自定义标签](App/Code/main.c:123)`
- 裸引用与中文文字之间要留空格（或用行内代码包起来），否则路径会被误粘连

围栏代码块内的引用不会被转换；已是 `vscode://` 的链接不会二次转换（幂等）。

文档写完后执行一次：

```
py -3 ${CLAUDE_PLUGIN_ROOT}/scripts/cjt.py convert <doc.md> --format json
```

- 报告中 `misses` 为空 → 完成。
- 有 miss → 按 `reason` 核对该引用（`file-not-found`/`line-out-of-range` 通常是路径或行号写错；路径必须相对**工作区根**），改正文档后重跑。
- 文档在被引用仓库之外（如 Obsidian vault）→ 加 `--root <仓库根>`。
- 只要一条链接：`py -3 ${CLAUDE_PLUGIN_ROOT}/scripts/cjt.py link path:line [标签] --format json`。
- 文档本身就是主体、只想在侧边栏留一个「这份文档的跳转点」平铺文件夹时，convert 加
  `--tags --name "<名称>"`；重跑幂等，文档删改后再跑一次即同步。**要分类/分层就走 A。**
  已转换文档单独补写：`py -3 ${CLAUDE_PLUGIN_ROOT}/scripts/cjt.py tags <doc> --name <名称> --format json`。
- 单条进收件箱：`link path:line [标签] --tags`。

## 前提（对人说明，遇到"点了没反应"时提示用户）

- 需已安装 VS Code 扩展 Code Jump Tags（patrick1099.code-jump-tags）；A 需 ≥ 0.9.0。
- 点击时 VS Code 打开的第一个工作区文件夹必须是链接路径的根。
- 侧边栏实时刷新需扩展 ≥ 0.8.0；旧版需 Reload Window。
